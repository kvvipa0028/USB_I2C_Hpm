# `uds-mock-fixture` v1：P1 模拟流程包格式

本目录的 `.udsmock` 文件是 UDS Bootloader「真实执行路径（骨架）」在 P1 阶段使用的**演示格式**，由 `src/flow/mock.rs` 的模拟后端（`MockBackend`）读取。它是为 P1 宿主、离线检查和模拟事件演示临时设计的，**不是** ODX / PDX / OTX / PTX、vFlash 或任何厂家格式，也不代表首个真实流程资产的形态（见提案 D01）。

用这种格式「准备」「执行」得到的一切都是模拟：不打开总线、不经 USB、不发送 UDS 请求，结果不能作为刷写、校验或应用版本的证据。

## 内置示例

| 文件 | 演示内容 |
| --- | --- |
| `single.udsmock` | 单入口，全部项目受支持；可准备、启动到「成功（模拟）」，也可演示停止 |
| `multi.udsmock` | 三个入口，检查后不预选，必须明确选择；`cal` 在校验步骤失败，`lost` 在下载中途后端失联（结果未知） |
| `blocked.udsmock` | 缺少依赖、未知扩展、外部脚本和不支持的步骤类型；检查列出每一项并阻止准备 |

同名的 `*.udsflow.json` 是同一内容的 JSON 清单（`uds-flow-manifest` v1，由 `src/flow/manifest.rs` 解析，仍为模拟、不是 ODX）；模拟后端和界面目前还只读 `.udsmock`。

这三份 `.udsmock` 通过 `include_str!` 编进程序，在页面「来源」里直接选择；也可以复制一份改动后，选「本地文件」并填写路径读取（上限 256 KiB）。

## 语法

UTF-8 文本，逐行读取。空行和以 `#` 开头的行忽略；行尾注释**不支持**（`#` 会成为值的一部分）。其余每行是 `键 = 值`，或分节 `[entry <ID>]`。第一个分节之前是包头，之后的字段属于最近的入口。

### 包头

| 键 | 含义 | 检查 |
| --- | --- | --- |
| `format` | 必须是 `uds-mock-fixture` | 否则「无法识别」，不进入检查结果 |
| `version` | 必须是 `1` | 其他版本记「不支持」，阻止全部入口；缺失记「缺少依赖」 |
| `package` | 包名，显示用 | 缺省用文件名 |
| `files` | 包内文件清单，逗号分隔 | 只是名字清单；镜像内容不读取 |

包头出现其他键记「不支持」（不跳过）。没有任何入口记「缺少依赖」。

### 入口 `[entry <ID>]`

| 键 | 格式 | 检查 |
| --- | --- | --- |
| `title` | 文字 | 缺省用 ID |
| `ecu` | 文字 | 缺失记「缺少依赖」 |
| `image` | `文件 \| 起始地址(十六进制) \| 字节数` | 文件不在 `files` 中记「缺少依赖」；地址越界、长度为 0 或无法解析记「不支持」 |
| `needs` | 文件名 | 不在 `files` 中记「缺少依赖」（例如 Flash Driver） |
| `step` | `类型 \| 名称` | 类型限 `read_id` `session` `security` `erase` `download` `verify` `reset`；其他类型记「不支持」。`erase` `download` `reset` 视为有副作用。没有步骤记「缺少 Flash Job」；有 `download` 但没有 `image` 记「缺少依赖」 |
| `param` | `ID \| 名称 \| 单位 \| 下限..上限 \| 默认值` | 可修改的整数参数；默认值来源记为「流程文件」；范围或默认值无效记「不支持」 |
| `const` | `ID \| 名称 \| 值` | 只读参数，原样进入运行计划 |
| `requires` | 任意文字（如 OTX 扩展名） | 模拟后端不提供任何扩展，一律记「不支持」 |
| `script` | 文件名 | 记「不支持」，并在检查结果注明「只记录，未执行」 |
| `simulate` | `fail@<步骤类型>` 或 `lost@<步骤类型>` | 故障注入，只影响模拟时间线；指向不存在的步骤记「不支持」 |

入口里出现其他键记「不支持」。ID 重复记在包级。任何一条「缺少依赖」或「不支持」都会阻止该入口准备；包级问题阻止所有入口。

## 模拟时间线

- 每个步骤 700 ms；`download` 分 4 段，每段报告一次「已确认下载字节」，与步骤进度分开显示。进度条按已完成步骤计，不按时间估算。
- `simulate = fail@X`：步骤 X 结束时返回否定响应（模拟 NRC 0x72）→ **失败**；若 X 有副作用，结果注明目标可能已部分改变。
- `simulate = lost@X`：步骤 X 进行到一半时后端失联 → **结果未知**，在途请求列为未确认；不自动重连，也不继续。
- 停止：后端接收停止请求后，任务进入「停止处理中」。若正在 `download`，在下一段边界停止且不等待已发出那一段的响应 → **结果未知**；其他步骤先完成当前步骤再停止 → **已停止**，已完成的副作用步骤（如擦除）列在报告里。接收停止请求不等于 ECU 已停止，也不表示回滚。
