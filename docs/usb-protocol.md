# USB-I2C 协议与 P0 扩展

日期：2026-11-06；实现状态更新于 2026-11-07。本文规定基础协议与 P0 扩展，当前固件源码已实现 `0x02/0x11/0x12`，上板验证仍待完成。新增端口控制见 [control-protocol-v1.md](control-protocol-v1.md)。Host/native 测试与 target 编译不能证明双路物理并发或实际速率通过。

## 1. 公共格式与兼容性

设备使用厂商接口，Bulk OUT `0x01`、Bulk IN `0x81`；每次一请求、一回复。多字节整数均为 little-endian。

请求头 8 字节：`cmd u8, seq u8, addr u8, reserved u8=0, wlen u16, rlen u16`，随后为 `wlen` 字节负载。`wlen/rlen` 的具体含义见命令表。

回复头 8 字节：`cmd u8, seq u8, status u8, reserved u8=0, hpm_stat u32`，随后为数据。`cmd/seq` 必须匹配当前请求，保留字节必须为零。状态：0 OK、1 NACK、2 I2C Timeout、3 BadRequest、4 I2cError；未知状态不得视为成功。

旧 `PING 0x01` 的版本仍为 1，不因 P0 扩展改为 2；旧 `I2C 0x10` 始终指 CH0，保留字节不编码端口。CH0 不是 master 时应明确拒绝，不隐式切角色。旧主机可继续发送旧报文。

| 命令 | 状态 | 请求与回复 |
| --- | --- | --- |
| `0x01 PING` | 已有固件/host | 请求 addr/wlen/rlen 均为 0；成功数据为版本 `1` + ASCII 固件标识，数据最多 64 B |
| `0x02 CAPABILITIES` | host/固件已实现；待上板验证 | 只读，请求 addr/wlen/rlen 均为 0；成功数据见第 2 节 |
| `0x10 I2C` | 已有固件/host | addr 为 7 位地址；wlen/rlen 分别为写/读长度，各 0–256，不能同时为 0；写后读使用 repeated START；成功回复恰好 rlen B |
| `0x11 I2C_PORT` | host/固件已实现；待上板验证 | 显式端口和速率，见第 3 节 |
| `0x12 I2C_BATCH` | host/固件已实现；待上板验证 | 每端口一笔的有界批次，见第 4 节；不属于通用脚本/命令序列 |
| `0x20–0x22`、`0x30–0x32`、`0x40` | UDS/CAN/ISO-TP 规划保留 | 见 `uds-isotp-firmware-plan.md`；本轮不复用、不广告为已实现能力 |

## 2. 能力查询与严格 legacy 降级

`CAPABILITIES` 的成功回复要求 status=0、hpm_stat=0、数据恰好 20 B：

| 数据偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | u8 | P0 extension version，当前为 1，与 PING version 独立 |
| 1 | u8 | port_count，当前允许 1–2 |
| 2 | u8 | flags：bit0 显式端口传输；bit1 双端口批次；bit2 自定义速率；其余位必须 0 |
| 3 | u8 | reserved=0 |
| 4 | u16 | 每次写、读各自最大长度，1–256 |
| 6 | u16 | batch 每端口写、读各自最大长度；不支持时为 0，支持时 1–240 且不超过单笔上限 |
| 8 | u32 | 默认速率 Hz；不支持自定义时即固定速率 |
| 12 | u32 | 最低支持速率 Hz |
| 16 | u32 | 最高支持速率 Hz |

速率范围必须在 10,000–1,000,000 Hz 内，默认值处于区间；不支持自定义时最小、最大、默认三个值相同。batch 要求 port_count=2 且支持显式端口传输；不支持显式端口传输时只允许单端口固定速率。上报能力是固件合同，不是硬件验收报告。

**唯一允许降级的回复**：完整 8 B、cmd=0x02、seq 匹配、status=3、reserved=0、hpm_stat=0、无数据。这是当前旧固件对未知命令的精确回复。此时 host 使用 legacy 能力：仅 CH0、100kHz、每方向最多 256 B；不发任何扩展传输。

USB 超时/错误、短包、错序、非零 reserved、带数据的 BadRequest、非零 hpm_stat、未知版本/能力位或自相矛盾的能力都不能降级。它们使会话失效，必须明确重连。能力在连接内缓存，重连重新查询；不从固件标识文字推断能力。

## 3. 显式端口传输

`I2C_PORT 0x11` 请求头的 addr 为 7 位 I2C 地址，reserved=0，wlen=`8 + 写数据长度`，rlen 为实际读长度。负载为：

```
port u8, reserved[3]=0, speed_hz u32, write_data[]
```

端口目前为 0 或 1；速率必须满足设备广告范围。写、读各最多 256 B，不能同时为空。完整请求最大 272 B，仍可放入现有 512 B 接收缓冲。长度、端口、角色与速率在启动总线动作前校验；非法请求不产生总线副作用。

成功回复 status=0、hpm_stat=0、数据恰好 rlen B。失败回复用公共错误状态，无数据；完整匹配的固件错误不作废 USB 会话，但不自动重放事务。未知状态、错误回复带数据、成功时 hpm_stat 非零或长度不符都是协议错误，作废会话。

这里的 speed_hz 属于该笔事务的明确参数，不代表 host 已完成时序验证。正在进行的事务不得被另一配置请求中途改变。两端口活动重叠需要固件实际并行推进，host 发送接口或 mock 并不证明这一点。

## 4. 有界双端口批次

`I2C_BATCH 0x12` 只允许恰好两项，CH0、CH1 各一笔；请求顺序可以是 0/1 或 1/0。每项写、读各不超过 240 B，也不能超过设备广告上限。host 与固件都先校验整个批次，非法第二项不能在第一项已执行后才被发现。

请求头 addr=0、reserved=0，wlen 是完整负载长度，rlen 是最大回复负载长度（不含下面说明的 USB 填充）。负载：

```
count u8=2, reserved u8=0
重复 2 项：port u8, addr u8, wlen u16, rlen u16, speed_hz u32, write_data[wlen]
```

请求最大 `8 + 2 + 2×10 + 2×240 = 510 B`。批次是单条 USB 请求、单条 USB 回复，固件内部需同时推进两路，不能实现成两次同步旧命令后宣称物理并发。host 不以两次旧 `I2C` 调用替代不支持的 batch。

正常批次回复的公共 status/hpm_stat 都为 0，数据：

```
count u8=2, reserved u8=0
按请求顺序重复 2 项：port u8, status u8, data_len u16, hpm_stat u32, data[data_len]
```

每项成功时 status=0、hpm_stat=0、data_len 等于该项请求的 rlen；每项失败时无 data。一个端口的 NACK/Timeout 不抹掉另一端口的确认结果。host 必须校验两个端口、顺序、数量、状态和长度后，才整体返回结果；不截断、不用 zip 忽略缺项。未知状态、错端口、短包等作废整条 USB 会话，不重放批次。

全批次在执行前被拒时允许公共 status=3、hpm_stat=0、无数据；它是已匹配的固件错误，会话仍可用。其它未定义的公共错误形式作协议错误处理。

未填充回复最大 `8 + 2 + 2×8 + 2×240 = 506 B`。**若整条实际回复（含 8 B 头）长度为 64 的整数倍，固件必须追加且只能追加 1 个零字节**；此规则在 FS/HS 一致，host 依据完整解析后的长度严格验证。原因是部分失败会缩短回复：若实际回复恰为 full-speed MPS，而 host 按最大成功长度申请 IN，缺少短包会一直等待。填充后仍不超过 507 B，不使用额外回复或事后 ZLP 搞乱单响应边界。

## 5. USB 边界、恢复与验证

所有请求（含旧命令、`I2C_PORT` 和 `I2C_BATCH`）在 `8 + wlen` 为 USB endpoint MPS 的整数倍时，host 在负载之后追加且只追加 1 个零字节，以 short packet 结束；其它长度不添加填充。`wlen` 只计算命令负载，不包含该字节；固件按 `wlen` 解析并忽略此唯一传输填充，不把它当 I2C 写数据或 batch 项。所有本轮帧都必须保持小于 512 B。回复的接收容量向 endpoint MPS 向上取整。

保持原有有界 PING 同步和单 session 规则；能力查询在同步之后执行。同步丢弃阶段的 IN 容量为 512 B，以覆盖旧单笔和新批次最大回复；不在数据中搜寻貌似 PING 的片段。固件仍须保持有界的单请求/单回复槽，不能私自增加无界完成队列。任何协议/USB失败均清理并作废会话，不自动重试 I2C。写事务失败时可能已经产生部分或完整副作用，USB 取消和重新连接都不能撤销；固件 Timeout 与 host USB Timeout 分别记录。

Host 验证至少覆盖：旧 golden vectors、严格降级的正反例、未知/非法能力、显式端口/批次布局、长度/速率边界、batch 部分失败与完整回复校验、FS 精确 MPS 及最大旧批次回复重连、固件 NACK/Timeout 保留会话、USB 超时/错序作废且请求只发送一次。真实设备仍需补：旧/新固件互通、WinUSB、全速/高速 USB、端口引脚及实际总线/时序/并发测量。

## 6. 明确的 offline 后端边界

GUI/CLI 共用 `Device` API；只有显式调用 `Device::offline()` 才进入模型。USB 枚举、打开或同步失败绝不自动转 offline。模型不打开 USB，每次构造时创建两路独立、全零的 256 B EEPROM 表，地址固定为 0x50；其它合法 7 位地址返回 NACK。偏移为第一写字节，后续数据自增写入，读从当前偏移自增，0xFF 后回绕。

模型允许 10kHz–1MHz 速率参数，但只验证范围，不计算线时序。批次先校验两项再依次更新两个独立模型，保留逐端口成功/NACK 结果；它不是并发时间仿真。进程退出/重建后表清零，不提供持久化或设备从机表同步能力。

`DeviceError` 的 session_invalidated 表示会话是否已作废，result_unknown 保守标注已提交 USB 写失败的结果未知。第 4 节定义的执行前全批次拒绝具有明确未执行结果，因此这两个标志均为 false。offline NACK 和本地拒绝不会伪造 USB 失联或结果未知；新请求在已失效会话上被本地拒绝，也不代表它又执行了一次。以上模型测试只证明 host 功能与契约，不关闭任何需上板的 P0 验收。
