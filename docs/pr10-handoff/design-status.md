# PR10 候选设计状态

本页只整理既有设计和审查结论，不增加方案。当前结论是未通过全约束核验，不可据此实施。参见[总进度](../pr10-status-and-handoff.md)、[证明状态](proof-status.md)和[来源](sources.md)。

## 单一硬件入口是条件，不是豁免

候选将普通中断真正路由到一个 M 模式非向量、非抢占 trap。MEI、MSI、MTI 在该入口内软件分派。不是多个硬件 ISR 调同一个 helper，也不是同优先级分组。

纸面构建条件包括 `USE_NONVECTOR_MODE=1`、`DISABLE_IRQ_PREEMPTIVE=1`，完全不定义 `USE_S_MODE_IRQ` 和 RTOS 入口宏。部分文件对宏使用数值判断，trap 对 NONVECTOR 使用 ifdef，定义为0不能当作非向量模式。最终每个翻译单元、链接、反汇编和调用图均未验证。

写者按真实硬件入口计数时，整对象映射为条件成立。写者按 PLIC 源号计数时，多个源的分支仍会写 I2C、USB 和表，本候选不合规。

## 初始化与运行期所有权

R0 是对应中断尚未使能的初始化阶段。纸面截止点是完成初始化和发布后开启 MIE。运行期不能把 configure、abort、恢复、重连的所有权交回初始化。

M 写请求体、请求发布序号、结果消费序号、协议缓冲以及产品 GPIOC 和 IOC 恢复对象。T 写整张从机表、generation、I2C 寄存器、USB 回调和 DCD 状态、调度状态以及 siggen GPIOB 和 IOC。完整类别见[35类映射](ownership.md)。

E 和 N 分别使用 diag_E、diag_N，不写受管产品对象。NMI 路由、异常覆盖、停机电气行为仍未证。SDK trap 出口有软件 CSR 恢复，不能记为运行期没有 CPU 写者，也不将平台背景泛化为新的 F1–F3 必改。

## 已完成的纸面修订

- frame_roll 明确重置 spent、used、used_u、slices_this_frame 和 cnt。
- 每次进入列出 top、sniff、roll、gate、compare、poll 的成本，已门控端口的 sniff 行为也被写明。
- 请求和结果采用分开的单写者对象。body 在 release head 前写完整，读者 acquire head 后读取，读取后 release tail，容量检查阻止覆盖未消费结果。
- 表操作增加互斥定义。CAS 比较与翻转在同一 T 步完成，FROZEN 快照在发布前保持结果槽稳定，batch 在第一个 START 前完成两项校验。
- 嵌套回调只登记撤销或配置事件，由边界按 revoke 优先次序提交。bus_word 合并 epoch 与 configured，旧 pend_prime 在复位重建前清理。
- 计时器设计不再假定写过期 compare 后一定立即重入。已改为未来目标、写后核对及明确硬件前提，但这些前提尚未证明。

这些修订不闭合下列 C1–C3，也不证明发布、回绕、时限或全调用图已经在实现上成立。

## QUAR 业务结果与 DMA 租约分开

业务操作在成功、拒绝或撤销时产生结果。结果消费只释放业务结果槽。

DMA 租约在硬件静止未证时继续钉住 QHD、qTD 和 payload。buf_return 只有在相应静止或完成证据获接受时才发布。业务失败、epoch变化、超时或结果槽释放都不允许 CPU 重用缓冲。

QUAR 可以永久占据某端点的静态租约项，端点不再 prime。这给出了有限隔离容量的纸面结构，但没有恢复该端点，也不能限制任意错误 DMA。没有 V_Q 或 V_R 时，正常 USB 复位、EP0 被新 SETUP 取代、在途配置变化仍可能到 DEAD，原可用性合同未满足。

C3 还表明业务 op 已回收、租约仍存在时，旧 l.op 的引用规则没有完整定义。不能仅凭“结果只发布一次”宣布恰好一次和内存存活已证。

## C1 子队列公平性未闭合

子队列已经耗尽本帧配额后再次就绪，其他队列仍有配额，轮转会继续选择其他队列。“至多 NU 个 U 片”不能由当前规则推出。

oldest_ready_u 回退的年龄更新、配额和轮转计数规则也不完整。本次只记录缺口，不引入新调度方案。

## C2 定时重复唤醒与成本界未闭合

D 配额耗尽后，过期槽是否仍参与 next_wake 未定义。按现文字，过期槽可使 program_wake 反复安排近期 MTI，而该槽因配额耗尽不执行。单槽重复进入次数不受原每帧进入数式子的静态槽数限制。

rr_pick 返回 NONE 的成本也未完整记账。因此每帧强制成本、M 进度、门铃合并后的拾取界和饥饿界仍待证明。硬件计时器前提即使成立，也不能代替这项内部证明。

## C3 租约可能引用已复用的 op

已有交错是：A在途，revoke发布A失败并回收op，该op槽被B复用，旧DMA仍未静止，再次revoke又遍历旧PINNED租约。文档未定义旧l.op如何脱离该槽或校验稳定代号。

这是纸面存活和幂等义务，不是已实施代码出现UAF的结论。容量算式不证明指针存活。本次不补新方案。

## reset 与 START 的边界

原F1要求防止ISR已处理复位、任务仍启动旧请求。候选将观察撤销、epoch检查和CMD线性化交由T，给出条件推理。

物理复位到URI可见之间没有硬件联锁证据。已经ACK的效果不可撤销。不得默认接受该窗口，也不得把更强的物理零窗口自动增设为已确认原合同。既有abort、STOP和电气效果仍需核对。

## 有限返回不等于硬件结束

PRIME、FLUSH、SETUP tripwire、close和可达驱动循环的限次分片只是软件结构。MMIO本身是否有界、完整回调是否有界、DMA何时静止、cache与总线次序、双芯片差异都缺关键证据。

只有明确所有前提和完整成本后，符号式才能作为条件界。板测只能提供观测，不能证明未给出上界的路径有界。[厂商问题](vendor-questions.md)尚未发送。
