# PR10 证明状态

本页是既有审查结论的整理，不补新设计。所有“已证”仅限来源事实或明确的纸面定义，不表示实现或形式化验证已经通过。C1–C3 的最终限定优先于早期草稿中的“内部缺陷已全部修正”。

## 状态词

- 已证事实：源码或官方文档直接显示，范围见[来源](sources.md)。
- 条件设计：列出的前提全部成立时才可使用，尚未在实现中证明。
- 未证：缺硬件证据、合同定义、完整推导或实现核验。
- 不成立：本候选有对应反例，或不满足既有合同，不能以降低标准替代。

## 关键反例

- C1：某队列配额已满又就绪，其他队列还有较大配额，当前轮转可让它等超过NU个U片。
- C2：D片配额已满，过期槽仍参与next_wake，后续反复安排MTI却不执行该槽，原进入数式子不足。
- C3：A发布失败后op回收给B，A的DMA租约还在，旧l.op在再次revoke时可能指向B。文档没有排除该交错。
- USB恢复：没有静止证据时，正常复位、EP0新SETUP、在途配置变化都可能走到永久隔离或DEAD。有限业务通知不等于功能恢复。
- 物理复位：寄存器尚未锁存时，软件读取不到复位状态。不能据此断言所有硬件架构不可能，也不能默认接受旧START窗口。
