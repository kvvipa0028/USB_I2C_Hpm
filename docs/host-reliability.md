# 单桥会话与演示页可靠性

本次修改限定为一台 USB-I2C 桥接器的使用流程，没有新增多设备并行支持，也没有修改线上协议或固件。EEPROM 工具和 AD 记录仍是本窗口的演示功能，不代表真实 EEPROM 或 ADC 后端已经实现。

## 连接与循环

- 已有连接时必须先断开，再选择并连接设备。界面、应用动作处理和 USB worker 都拒绝直接替换连接，包括重复连接同一序列号。
- 顶栏显示实际打开的桥，而不是尚未连接的列表选中项。
- 连接动作、断开、连接结果和操作错误都会解除循环。重新连接后需要手动重新启动读写，不会恢复旧循环。
- 刷新只枚举 USB，不会自动重连。未被应用观察到的物理断线不能仅凭界面状态判定；热插拔行为仍需实机验证。

## USB 错误与恢复

正常 I2C NACK、固件返回的 I2C Timeout，与主机等待 USB 完成超时是不同情况。完整、匹配的固件错误回复仍保留可用的 USB 会话，但会停止界面循环。

发生主机 USB 超时、USB 传输错误或不匹配/损坏的回复后：

1. 会话立即失效，不能再通过该对象提交 I2C 请求。
2. 取消两个端点的挂起传输，并共用最多 100 ms 的清理等待预算。即使取消完成通知没有返回，也释放端点，不无限等待。
3. 界面清除连接状态，要求用户重新连接。含写入数据的失败请求明确提示“写入结果未知”。
4. 不自动重发任何 I2C 操作。取消 USB、断开或重新连接都不能撤销已经在目标器件上执行的写入。

重新打开连接只用 PING 做有界同步和固件版本检查，不用 I2C 写入探测恢复状态。先丢弃一个完整接收结果，再验证两个不同序号的 PING；这可清理全速 USB 旧整包回复与短 PING 合并的情况，不在任意 I2C 数据中猜测报文头。同步共用 2 秒等待预算，最多接收 8 个结果。该方法依据当前固件单个 RX/TX 缓冲及串行执行行为；回复丢失或损坏时仍拒绝建立连接。同步不能确认上一笔写入是否执行，也不能代替硬件复位。连接仍失败时，按错误提示重新连接或重新插拔 USB；先确认目标器件状态，再决定是否重新执行有副作用的写入。

正常事务继续按预期回复长度和端点最大包长分配 IN 缓冲，避免破坏全速 USB 下恰好占整包、没有额外 ZLP 的回复。

## EEPROM 演示镜像

- 容量改变当帧就重新计算页码与视图范围。
- 正在执行的任务锁定容量、配置恢复和读写计划编辑；任务保留检查时的配置用于执行和报告。
- 缩小容量不清除镜像后部字节，重新扩大后仍能看到原演示数据。镜像只在窗口生命周期内存在。
- 执行和读回使用受检范围。异常内部状态显示验证失败，不再因越界切片崩溃。

## AD 演示采样

- 以记录开始后的真实经过时间计算到期样本，不再把每次 50 ms 刷新的样本数向上取整。
- 第 k 个样本在 k/rate 秒到期，时间戳同样为 k/rate，k 从 1 开始。包含配置时长边界上的最后一个样本；第一次到达或超过结束时刻的刷新结束记录。
- 每次刷新最多生成最新 4000 个到期样本。长时间没有刷新时，更早的到期样本计入“丢样”，时间戳保留时间间隔，不在后续刷新补发旧积压。
- 这只修正合成信号的计时，不包含真实 ADC 精度、采样频率或电气验证。

## 回归与验收边界

在 `host/` 下运行：

```sh
cargo test --workspace --all-targets --locked
cargo build --release --workspace --locked
cargo clippy -p usb-i2c -p usb-i2c-gui --all-targets --locked -- -D warnings
cargo check --workspace --all-targets --locked --target x86_64-pc-windows-msvc
```

仓库内新增测试覆盖 USB 队列超时/取消/迟到与缺失回复、全速包合并和残留 PING、单 RX/TX 缓冲模型、不自动重放、正常 I2C 错误、单桥连接状态、EEPROM 实际 egui 点击序列，以及 AD 多档速率、时间边界、非均匀刷新和长暂停。另有 13 页 × 2 主题 × 3 窗口尺寸的无显示渲染检查，只检查有限几何结果，不等于原生窗口或截图验收。USB 模型测试使用生产会话逻辑和 nusb 的完成类型，但不执行真实 USB 驱动或物理总线事务。

仍需在实体 HPM6300EVK 与目标器件上验证：连接/PING、I2C 读写、实际 USB 超时注入、全速/高速切换、热插拔、重连后残留回复，以及“写已经执行但确认丢失”的处理。Windows 交叉检查不是 Windows 运行测试。EEPROM/ADC 无需接硬件即可复现和验证此次演示页修复。
