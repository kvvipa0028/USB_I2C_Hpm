# T1.9 从机寄存器表测试记录

日期：2026-11-01 · 对应：DEV_PLAN T1.9、风险 R1、PRD FR-SLV-01~05

## 结论

- 100k，两板直连、只有 EVK 内部上拉：**通过**（运行 A，复测运行 F）。200 轮零错误，两边寄存器表逐字节一致；
  运行 F 中 200 轮用时 10.253s，有效速率不低于 98.7kHz。
- 接着 10kΩ 上拉期间（运行 B~E），100k 和 400k 都失败；改回两板直连后 100k 恢复（运行 F）。
  所以失败出在当时的电阻接法上，**400k 还没在正确接线下测过**。
- 0~254 单次写入（100k，两板直连）：从机完整收到 255 个字节，偏移和顺序都正确，见下文。

## 环境

- **从机**：HPM6300EVK，I2C0 = J28[13] SCL / J28[15] SDA，跑 `firmware/slave_proto`（地址 0x50，256 字节表，
  中断驱动，每个接收字节手动 ACK）。引脚开了内部上拉。
- **主机**：HPM6750EVKMini，I2C0 = P1[13] SCL / P1[15] SDA，跑 `tools/slave_test`。SDK 默认不开内部上拉，
  `PEER_PULLUP=1` 时打开。
- **接线**：两板 SCL–SCL、SDA–SDA、GND–GND，杜邦线。运行 B~E 期间另接了 1 个 10kΩ 上拉到 3.3V（接在哪根线上未确认）；运行 F 时改为两板直连，不接电阻。

## 方法

每轮 9 次驱动调用：整表写（1+255 字节、1+1 字节）→ 随机读整表 256 字节 → 当前地址读 4 字节（读满 256 字节之后）
→ 当前地址读 4 字节 → 随机读 0x80 起 10 字节 → 当前地址读 6 字节（应从 0x8A 接着读）→ 写 0xFE 起 4 字节（跨表尾）
→ 随机读 0xFE 起 4 字节。每次读回都和主机侧模型 `g_exp` 逐字节比对。共 200 轮，最后用 JTAG 读出从机的
`g_table` 与 `g_exp` 比对，再核对从机的事务计数（每轮应为地址命中 12、写事务 6、读事务 6）。

## 0~254 单次写入测试

主机（`SEQ_ONLY=1`）发一次写事务：先发偏移 0x00，再发数据 0、1、…、254，共 255 个数据字节。接线同运行 F（两板直连，100k）。
测试前重新烧录从机，寄存器表全为 0；写完后用 JTAG 读出整张表。

| 项 | 结果 |
|---|---|
| 主机写调用 | 成功（status 0），用时 23.4ms，有效速率不低于 99.0kHz |
| 从机计数 | 地址命中 1、写事务 1、读事务 0 |
| 从机表 | table[0..254] = 0..254，逐字节正确；table[255] 仍为 0，没有被写到 |

table[0] 写入前就是 0，单靠这次测试无法确认它被写过，这一字节由运行 F 的 200 轮测试覆盖。原始日志：`T1.9-data/seq-0-254-*`。

## 故障现象（B~E 相同）

- 主机：每次调用都在地址阶段收到 NACK（`status_i2c_no_addr_hit` = 2003）。STATUS 中 SCL、SDA 均为高，无仲裁失败。
- 从机：ADDRHIT 一次都没置位（这一位由硬件置位，与固件无关），但 STATUS 显示检测到过 START 和 STOP。
  寄存器配置正确：地址 0x50；400k 时 SETUP = 0x009023d1，与主机的 fast 模式时序一致。
- 解读：从机看到了 SDA 的跳变，但没有正确采到地址位。可能是 SCL 没接到从机，或者某根线的电平不对。
  接电阻之前 100k 是通的，所以先查接电阻时的改动。
